Personal control plane / interactive contract model

Four devices.
One place to coordinate.

A small router on mbp carries requests between you, one coding orchestrator, a knowledge assistant and two device services. Jev decides who owns an unaddressed request; code handles everything else.

Every button runs the tested contract. This page drives router-core.js, the same pure module that router-core.test.js checks, loaded with one example deployment from router-example-config.js. The router itself carries no deployment. Jev answers, adapters and participants are scripted; nothing leaves this page, and refreshing resets it.

Devices and placements

A placement is a participant on a device, with one current session. The router sends only when a fresh observation says the session is idle, and never while one of its sends is unconfirmed. How many open tasks a participant works on at once is its own decision.

Participant directory

From the example configuration, not built into the router. Jev reads these responsibilities in full; permissions decide who may address whom.

Jev decision

One scripted Choice over the sender's permitted participants plus none. Below the threshold, the sender chooses. Addressed requests and replies use no judgment.

    A summary. The event table in jev-router-spec.md is authoritative. 

    submit         { messageId, text, to?, hosts? }  → receipt (same key + content = same task)
judged         { choice, probabilities }         → recipient, or ask the sender
attempt        { deliveryId }                    → recorded first; session marked busy
adapterResult  accepted | not_sent | unknown     → not_sent requeues; unknown retries
                                                   only with the same deduplicated key
update         { inReplyTo, kind }               → working | question | completed | failed
                                                   progress after a question settles it
answer         { questionId, text }              → queued to the same pinned session
observe        { ready?, hold?, session? }       → idle gate; hold = you are in the session
resolve        (operator) finished | not_sent    → closes uncertainty; never resends

Identity: sender principal + messageId. A reply must come from the
delivery's pinned session and answer its current message.
