What happened

    What this architecture keeps small

    One local process

    The intended service owns the directory, decisions, delivery records, and replies. Its first implementation can use one SQLite file and plain functions.

    In this model, a request takes at most two Jev judgments. Code loads fuller descriptions between them. Explicit targets and replies use zero judgments.

    One delivery contract

    An adapter receives an endpoint and a correlated envelope. It reports delivery evidence and replies with the same identifiers. The router owns task state and decides what those reports mean.

    The script walkthrough adds a second adapter to the same lifecycle. It tests the proposed interface; it does not implement a second runtime.

Rule: accepted delivery is not completed work.
Rule: repeated identity + same content returns the existing task.
Rule: an uncertain delivery is never automatically sent again.
    
        
    
        
    
          What the Claude probe established
          
    
            On this host, the installed Claude Code 2.1.283 binary supports
            programmatic print mode, structured results, and a caller-selected
            session ID. A router-owned turn is a concrete first transport to
            test. The normal launcher currently tries to install a version; the
            probe used the installed binary directly.
          
    
          
    
            Existing sessions can be listed externally, but their supported
            listing does not expose inbox sockets. Adopting an already-open
            terminal needs an opt-in registration mechanism and a verified reply
            path. This prototype does not claim those integrations work.
          
    
          
    
            No live Claude message or Jev inference was needed for this
              model.
            A process launch alone would not prove message acceptance. A Claude
            adapter may go straight from an attempted delivery to a correlated
            final result, without a separate acceptance receipt.
          
    
        
    
        
    
          Questions the real transport still has to answer
          
    
            Does an actual send produce a trustworthy receipt? Can a reply be
            correlated without trusting generated text? What survives a process
            or disk failure? What should the user do when delivery stays
            unknown?
          
    
          
    
            The model parks uncertain delivery until a matching result arrives.
            It has no automatic retries, task cancellation, remote enrollment,
            or general workflow editor. Multi-host transport and measured Jev
            accuracy remain separate experiments.
