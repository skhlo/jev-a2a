What happened

    The communication contract

    Router: carry the conversation

    Accept a request, resolve its recipient, record delivery, match replies and make the result available from any view. Small Jev judgments help interpret ambiguous requests. Code handles identities, known targets, device availability and duplicates.

    Orchestrator: run the workflow

    The one coding orchestrator owns the configured sequence for every repository. It can ask a service for a VM or a host observation through the same router. Workflow steps belong to that agent; dotfiles supplies its harness configuration.

          Placement, assumptions and limits
          
    
            This proposal uses one control-plane process and a SQLite journal on
            always-on mbp. The demo models one orchestrator across all
            repositories, plus one knowledge assistant on mini. Device
            operations use services; adding a repository or viewing device adds
            no persistent agent.
          
    
          
    
            Paseo and herdr are modeled access surfaces. Agent, host and Incus
            adapters are proposed interfaces with scripted outcomes. This page
            does not connect to them, GitHub or your dotfiles. Protocol
            authentication, transport, real persistence, throughput and latency
            still need an implementation experiment. The central service depends
            on mbp being reachable.
          
    
          
    
            The earlier Claude probe established a possible router-owned turn to
            test. Existing-session registration and verified reply correlation
            remain separate work. A restart here only changes browser state;
            refreshing the page clears the journal.
